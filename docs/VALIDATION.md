## October 14: bounded full-scramble improvement

The full-scramble adapter now retains its verified Kociemba-plus-shortcuts result, then searches for improvements using all three choices of phase-two axis. It reuses cubejs's initialized move/pruning tables without changing the vendored runtime or adding a dependency. Alternatives are scored by the guide's actual 90-degree steps, including two steps for half turns. Every accepted alternative is mapped back to the input's coordinates and applied to verify a solved state. A plan is finalized before opening the guide; it never changes underneath a user stepping through it. The exact search for states within six quarter turns still bypasses this extra work.

The extra search has a 200 ms deadline and a two-million-node ceiling, with clock checks every 128 nodes. Individual phase-two probes and phase-one depth passes are also bounded so one branch cannot consume the entire search. These deliberate limits mean it is **not a globally optimal solver**. The deadline applies to improvement work, not the existing initial solution, table initialization, worker startup, or camera capture. Timer-check granularity, verification, and scheduling can add a small overshoot; phone timings remain unmeasured. On expiry, the best verified incumbent is retained. See [Kociemba's explanation of continued two-phase search](https://kociemba.org/math/imptwophase.htm) and the [separate optimal solver](https://kociemba.org/math/optimal.htm).

Reproducible desktop comparison: `npm run benchmark:solver`, 40 deterministic 25-face-turn scrambles (seed 121, no consecutive same-face moves), warm tables. Compared with the preceding adapter's Kociemba-plus-shortcut plans, 31/40 shortened, none lengthened, and average quarter-turn steps fell from 32.3 to 29.0. The added search averaged 111.2 ms (p95 124.2 ms, max 142.8 ms); baseline solution generation averaged 47.6 ms, and one-time table initialization was 1,107.6 ms. The node ceiling can end the search before its time allowance. Every output was checked using the independent cubejs move engine. Exact results, scrambles, environment, and timings are saved locally in `artifacts/full-solution-results.json`. This is a modest measured improvement, not proof of shortest routes or phone performance; time-bounded results can vary with device speed and load.
